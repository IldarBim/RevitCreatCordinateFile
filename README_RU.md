# TATBIM Project Creator — исходный проект, v0.1 (Revit 2022)

Это **исходный код**, а не готовый проверенный установщик. Нужны Windows, Revit 2022, .NET SDK с поддержкой сборки net48 и .NET Framework 4.8 Developer Pack. Сборка в текущей среде не проверялась (Revit API DLL отсутствуют).

## Установка
1. Распаковать ZIP в каталог с доступом на запись; файлы Excel уже включены в `Data/Worksets`.
2. Запустить `install.bat` на ПК с Revit 2022. При успешной сборке плагин копируется в `%APPDATA%\Autodesk\Revit\Addins\2022`.
3. Перезапустить Revit 2022 и открыть вкладку **Надстройки → Внешние инструменты → TATBIM Project Creator**.
4. Указать корневой каталог **01. Проект**, проверить путь к Excel и для каждого раздела указать абсолютный путь к реальному `.rte`. Сейчас шаблоны в настройки не записаны: кроме АР, полноценные RTE не предоставлены.
5. Установить количество файлов по каждой строке (0 означает пропуск). Нажать «Предпросмотр» и «Сохранить настройки».

## Запуск и координаты
**Этап 1: SF.** Назначить шаблон SF и создать центральную модель `SF`. Плагин не придумывает геодезические координаты. Открыть SF в Revit, задать систему координат, истинный север, при необходимости высоты и точки привязки по исходной геодезии, проверить положение. Сохранить и закрыть SF. *Подтверждение — это действие ответственного BIM-координатора; программа автоматически не устанавливает координаты SF*.

**Этап 2: остальные модели.** После проверки SF установить галочку подтверждения, нажать «Создать остальные модели». Для каждой новой модели плагин создаёт Revit-документ из RTE, включает совместную работу, читает первый столбец первого листа Excel и создаёт отсутствующие рабочие наборы; связывает SF один раз по совмещению внутренних начал координат, получает общие координаты через `Document.AcquireCoordinates`, удаляет временную связь и сохраняет новую центральную модель.

**ВНИМАНИЕ ПО ПРИВЯЗКЕ:** Совмещение внутренних начал — **допущение первого прототипа**, а не универсальная геометрическая координация. Если внутренние начала моделей не соответствуют друг другу, должны быть применены заранее согласованные преобразования (смещения/повороты) связей относительно SF. Перед использованием на действующем объекте требуется проверка координат и совмещения геометрии тестовых моделей. Общие координаты не гарантируют совмещения здания без правильной геометрической привязки.

Результат `AcquireCoordinates` иногда выдаёт ошибку, например когда система координат уже совпадает или когда у SF несколько площадок. Ошибка записывается в журнал, а зависимая центральная модель не сохраняется. Ошибка на одном разделе не останавливает следующие разделы, это нужно контролировать в итоговом журнале.

## Наименования
`ШИФР-ИМЯ-КОД-ОБЩЕЕ-R22.rvt`, пример `999-YYY-AR-ALL-R22.rvt`. При Count > 1 программа временно добавляет двухзначный индекс **к сегменту ИМЯ**: `999-YYY01-AR-ALL-R22.rvt`, `999-YYY02-AR-ALL-R22.rvt`. Прежде чем использовать этот режим на рабочем объекте, утвердить схему именования. Все папки уже существуют — программа не создаёт каталогов назначения и не перезаписывает RVT.

## Excel
В архив включены предоставленные пользователем `.xlsx`. Читается первый столбец `A` листа `sheet1.xml` (первый лист); поддерживаются sharedStrings/inlineStr. Для SF временно выбран `Рабочие наборы_Связи.xlsx` — необходимо подтвердить, что это правильно. Для GS Excel пока не задан и GS не будет создан до назначения справочника. Коды `KR`→КЖ и `SS`→CC требуют подтверждения соответствия.

## Ограничения версии 0.1
- Координаты SF устанавливаются и проверяются BIM-координатором; автоматическая геодезическая настройка SF не реализована.
- Автоматическое распределение объектов внутри созданных наборов не реализовано.
- Сохранение central поддержано; тестирование на действующем Revit 2022 обязательно, так как в среде создания нет установленных Autodesk DLL.
- Пока нет ленточной панели и install setup.exe: команда доступна в «Внешних инструментах».
- Схема `RevitLinkType.Create` + `AcquireCoordinates` требует испытаний с вашими RTE, особенно для моделей с предварительно существующими связями или несколькими площадками.
- Если в исходном RTE уже есть совместная работа, обработка зависит от его фактических свойств; требуется проверка.

### v0.2.0 — рабочие наборы
Два обязательных начальных пользовательских набора Revit получают имена из Excel: первый Shared/00_Shared, второй LINK/01_Link. Workset1 не создаётся отдельно. Другие имена из Excel добавляются при необходимости. Если в Excel нет двух подходящих имён, создание модели останавливается с диагностикой. У существующих совместных шаблонов наборы сохраняются, автоматического удаления нет, чтобы избежать потери элементов. Обратите внимание, что уже созданные RVT не изменяются повторным запуском.


## v0.2.1 — правила имени RVT
Количество 1: 999-YYY-AR-ALL-R22.rvt.
Количество больше 1: 999-YYY-AR-BS1-R22.rvt, 999-YYY-AR-BS2-R22.rvt и т.д.
Нумерация начинается с 1 отдельно для каждого кода модели.


## v0.2.2: Взаимные связи RVT
После создания всех моделей включается загрузка всех RVT друг в друга (кроме самого себя). Также доступна кнопка "3. Связать RVT" для повторного запуска. Связи размещаются по Shared Coordinates; рабочий набор выбирается по LINK_<КОД>, 01_Link_<КОД>, или при отсутствии создаётся LINK_<КОД>. Для сохранения изменений создаётся временная локальная копия и выполняется Sync With Central. Внимание: опробовать на тестовом комплекте, проверив координаты, до применения в проекте.

## v0.2.10 — дополнительная группа моделей
В таблице добавлены две отдельные колонки: «Доп. префикс» и «Доп. кол-во». Существующая колонка «Кол-во» работает как раньше: одна модель — общая часть (например ALL), несколько — BS1, BS2, BS3. Новая группа добавляется к основной.

Пример для AR: «Кол-во» = 3, «Доп. префикс» = PP, «Доп. кол-во» = 2 создают пять файлов: 999-YYY-AR-BS1-R22.rvt, 999-YYY-AR-BS2-R22.rvt, 999-YYY-AR-BS3-R22.rvt, 999-YYY-AR-PP1-R22.rvt, 999-YYY-AR-PP2-R22.rvt. Префикс задаётся отдельно для каждого раздела. При дополнительном количестве 1 индекс не добавляется: 999-YYY-AR-PP-R22.rvt. При количестве 2 и более нумерация начинается с 1. Дополнительное количество 0 отключает новую группу; основное количество 0 позволяет создать только дополнительную группу.

Обе группы учитываются в общем количестве, предпросмотре, создании и взаимных связях. Они используют выбранные для раздела RTE, Excel и рабочие наборы. Дополнительное количество — целое число 0–99. Пустой префикс при ненулевом количестве, запрещённые символы и совпадающие пути файлов отклоняются до запуска. Для SF дополнительные модели не предусмотрены: SF остаётся единой моделью координации.

Настройки старых версий загружаются с дополнительным количеством 0. При обновлении заменяется только DLL; существующий settings.json сохраняется. Новые колонки сохраняются по кнопке сохранения настроек. Дефис в шифре проекта из версии 0.2.9 поддерживается.

Проверены сборка с Revit API 2022, загрузка старых настроек, ввод и сохранение новых колонок, имена и общий список моделей для предпросмотра/создания/связей. Создание и связывание настоящих RVT в Revit при этой проверке не запускалось.
